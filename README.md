## 一、系统简介

本系统用于对公司网络设备（路由器、交换机、防火墙、无线 AP、服务器、负载均衡、UPS、摄像头等）进行统一管理，解决以下问题：

- 设备资产分散、台账不清晰，难以快速查询定位；
- 维保维修过程无记录，责任与进度不透明；
- 设备借出后无人跟踪，长期占用、超期不还；
- 巡检结果无留档，故障追溯困难；
- 缺少全局视角，无法掌握设备总量、状态分布与采购趋势。

系统采用前后端一体部署：后端提供 REST API，前端页面由后端静态托管，**单端口（8080）即可访问全部功能**。界面采用简洁的莫兰迪色系设计。

## 二、功能模块

| 模块 | 说明 |
| --- | --- |
| 登录与权限 | 会话登录；ADMIN 管理员拥有全部权限，USER 普通用户只读 + 可提交维保/借还申请 |
| 统计仪表盘 | 设备总数/故障/维修中/借出等指标卡片；类型、状态、部门分布饼图；近 12 个月采购趋势折线图 |
| 设备管理 | 增删改查、多条件筛选（关键词/类型/状态/部门/位置）、分页、详情抽屉（图集 + 维修历史时间线）、多图上传 |
| 维保维修 | 申请 → 受理 → 完成/驳回 全流程；维修期间设备自动置为"维修中"，完成后恢复；多图留档 |
| 借出归还 | 申请 → 审批 → 归还 全流程；审批通过设备自动置为"已借出"，归还恢复"在用"；超期自动标红提醒 |
| 巡检记录 | 登记巡检正常/异常结果，多图留档 |
| 部门与位置 | 部门、位置（机房/楼层等）双卡片管理；被设备引用时禁止删除 |
| 操作日志 | 全模块操作留痕（登录、增删改、审批等），仅管理员可见 |
| 用户管理 | 管理员对用户进行增删改、重置密码、启用/禁用 |

**图片能力**：所有业务模块（设备、维保、借还、巡检）均支持多张图片上传，统一存储于服务器 `uploads/` 目录，通过 `biz_image` 表按业务类型 + 业务 ID 关联，删除业务数据时级联清理图片文件。

## 五、安装与启动

### 1. 初始化数据库

```sql
CREATE DATABASE netdev_db CHARACTER SET utf8mb4;
CREATE USER 'netdev'@'localhost' IDENTIFIED BY '你的密码';
GRANT ALL ON netdev_db.* TO 'netdev'@'localhost';
FLUSH PRIVILEGES;
```

> 数据库连接信息通过环境变量配置（密码必填，其余有默认值）。在项目根目录创建 `.env` 文件（不会被提交到仓库），`run.sh` 启动时自动加载：
>
> ```bash
> DB_PASSWORD='你的密码'
> # 可选：DB_URL='jdbc:mariadb://主机:端口/库名'  DB_USERNAME='用户名'
> ```
>
> 也可以临时导出环境变量：`export DB_PASSWORD='你的密码'`

### 2. 启动 / 停止

```bash
# 启动（自动构建 + 运行，首次启动自动建表并写入演示数据）
./run.sh

# 一键停止程序并释放 8080 端口
./stop.sh
```

若重启过电脑，请先确认数据库服务已启动：

```bash
sudo service mariadb start
```

## 七、接口约定

- 统一返回格式：`{ "code": 0, "msg": "ok", "data": ... }`
  - `code = 0` 成功；`code = 401` 未登录（前端自动跳转登录页）；`code = 403` 无权限
- 鉴权方式：HttpSession 会话，登录接口 `POST /api/auth/login`
- 主要接口前缀：
  - `/api/auth/**` 登录/登出/当前用户
  - `/api/devices/**` 设备（分页查询、CRUD、详情、维修历史）
  - `/api/images/upload` 图片上传（multipart：file + bizType + bizId）
  - `/api/maintenances/**` 维保（申请/受理/完成/驳回）
  - `/api/loans/**` 借还（申请/审批/归还）
  - `/api/inspections/**` 巡检
  - `/api/departments/**`、`/api/locations/**` 部门与位置
  - `/api/users/**` 用户管理（管理员）
  - `/api/logs/**` 操作日志（管理员）
  - `/api/dashboard/stats` 仪表盘统计

## 八、常见问题

**Q：启动报数据库连接失败？**
A：确认 MariaDB 已启动（`sudo service mariadb start`），且已按第五节创建数据库与账号。

**Q：提示端口 8080 被占用？**
A：执行 `./stop.sh` 释放端口后重新启动；或修改 `application.yml` 中的 `server.port`。

**Q：上传的图片存在哪里？**
A：项目根目录下的 `uploads/` 文件夹，通过 `/uploads/**` 路径对外访问。

**Q：如何清空数据重新开始？**
A：删除 `netdev_db` 数据库并重新创建，同时删除 `uploads/` 目录，重启后会自动重建表和演示数据。
